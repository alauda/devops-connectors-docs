## 站得住脚的商业论断（≤5 条）

1. **"data-plane proxy vs secret injection 是哲学差异，不是 license 差异"**（§7.1 / §1 论据 1）—— 这一条不依赖任何商业数字，只靠 PoC-1 / PoC-2 的可观测事实就能成立，是整份报告最硬的商业护城河论点。可直接进 sales 材料。
2. **"Connectors 与 Vault 不是替代而是互操作（ESO 作输入）"**（§3.4 / §10.2 动作 4）—— 这是一个**对客户友好的姿态**，正面把"客户已经买了 Vault" 的场景接住，避免把存量 Vault 客户推向竞品。商业上明显加分。
3. **"切换不能节省工程团队"**（§3.2）—— 6 组件供应链 + 客户 single point of contact 的论证逻辑链通，对 CEO 真正担心的"是不是该砍掉团队 / 外包给 HashiCorp"提供了可信的反向回答。
4. **"OperatorHub 一键装 vs Vault HA + unseal + 8 项生产化"**（§9.2）—— 这条是金融 / 国央 / 电信 air-gap 客户**真实买单的痛点**，且每一项都有具体动作清单可作 SE talking point，可信度高。
5. **"立项时即排斥凭据下发到 client 不是技术盲区而是产品定位选择"**（§4.4）—— 给 CEO "当年是不是没想清楚"的潜台词一个**可被审计的回答**（KEP-0001/0002、diff-with-3.x 行号），这种"敢承认没做过 Vault 正式评估、但有书面立项理由"的诚实姿态比硬辩更可信。

### P0 — "Vault Enterprise license $50k-$200k+/集群/年" 没出处且区间过窄

- 位置：REPORT.md §1 论据 2、§2.2、§2.4、§7.3、§10.1
- 现状：报告 4 处反复引用这个区间，但**全文没有任何脚注 / 链接 / 客户案例 / 第三方报告作为出处**；同时区间下限 $50k 与上限 $200k 只差 4 倍，**实际 Vault Enterprise 不同 SKU + node count + 模块（Namespaces / Replication / HSM / ADP）差异远超 10 倍**，且 HashiCorp 自 2024 起从 license 转 Resource Unit 计费，给的"集群/年"单位已经不是当前商业模型的主语。
- 质疑：
  1. 这个数字是从哪里来的？Alauda 历史成单中真的见过这个区间？还是 ChatGPT / 旧 blog 摘的？

  - 要么**老实标 "公开范围估算（来源：Gartner Magic Quadrant for Secret Management / HashiCorp 2024 价格指引 / Alauda 销售估算）"** 加脚注，要么**整段降级为"显著的独立 license 项，量级达年六位数美元 / 集群"** 这种**不可精确反驳的定性表述**。
  - 区间撑开到 $30k-$500k+ 更接近真实差异；明确标注计价单位变化（perpetual license → resource unit）；多集群总账加"假设单价不变，未考虑批量折扣"的免责说明。
  - 加一句对客可用的话术："具体价格客户需直接向 HashiCorp / IBM 取报价，我们的成本对比不依赖单价精确值，依赖的是 0（Connectors）vs 独立 SKU（Vault Enterprise）的结构差异。"

### P1 — "ACP 定价需相应下调 ≈ 5-10%（粗估）"是一颗自伤的炸弹

- 位置：§2.4 第一段
- 现状："若切换到 Vault，Connectors 价值从 ACP 整体打包中剥离，需相应下调 ACP 定价 ≈ 5-10%（粗估）"——**作者主动给出了 ACP 内 Connectors 的价值占比上限**。如果这份报告被竞品 / 客户拿到，会被反向使用："Alauda 自己承认 Connectors 只值 ACP 5-10%，那我们用其他方案替换它，给我们 5-10% 折扣就行。"

  - **删掉这条具体百分比**。改为定性表述："Connectors 是 ACP 平台与差异化能力的一部分，剥离会同时削弱平台 entitlement 价值与差异化卖点，但具体折损取决于客户场景，不在本报告量化范围。"

## 4 类决策者视角的盲点

1. **缺合规清单维度**：金融 / 央企客户的 IT 合规清单里 Vault 经常是"已审批 secret store"，Connectors 作为新组件需要走单独审批。这是合规决策者的真实纠结点，报告把合规角色一面倒地写成反对切换，反而漏掉了"客户合规要求保留 Vault" 的反向用例。
2. **缺 IBM 商务关系紧密客户视角**：IBM 在中国央企 / 金融领域有深厚商务关系，部分客户的 IT 标准是"IBM 系优先"。这类客户对"加买 Vault Enterprise" 的阻力远小于一般客户，4 类决策者表里完全没体现。
3. **缺已有 Vault 团队的客户视角**：客户内部已有专门 Vault SRE 团队的情况下，SRE Lead 的态度可能从"反对" 变成"中立 / 倾向 Vault"。报告需要明确"这类客户在 Alauda 客户池中占比" 来约束论断范围。
4. **缺开发者中"Vault 原生体验" 偏好者**：一部分开发者熟悉 Vault Agent / VSO，对 K8s-native CR 模型反而陌生，会反向投票。报告把"开发者明确反对" 写成一致姿态过于乐观。
5. **缺渠道 / SI 视角**：Alauda 在中国市场大量通过渠道 / SI 交付，渠道 SI 自身的技能栈和偏好（懂 Vault 与否、能否额外卖 Vault 实施服务）会影响推荐方向。报告完全没提渠道视角。

## 竞品定位的公平性问题

1. **OpenShift + Vault 的"自然组合" 缺渗透率数据**：详见 P1 第 6 条。建议加一句"我们没有公开渗透率数据" 或引用 Gartner，否则容易被读者识别为臆测。

## 是否回应了 CEO 全部潜台词

CEO 让做这个调研的潜台词，至少有 3 层：

| 潜台词 | 报告回应度 | 评价 |
|-------|---------|------|
| (a) 当年是不是没想清楚？ | ✅ 充分回应 | §4 历史追溯 + §4.4 直接回答，做得好 |
| (b) 现在是不是该切换到 Vault？ | ✅ 充分回应 | §5 / §6 / §7 多维度论证，硬证据扎实 |
| (c) 是不是该把 Connectors 卖掉 / 开源给 HashiCorp / 砍掉团队？ | ⚠️ 部分回应 | §3.2 论证了"切换不能节省团队"，但**没有正面回答**"那 Connectors 应该开源吗？应该独立成产品卖给非 ACP 客户吗？应该作为 ACP 的标配还是可选模块？"——这些是 CEO 在"不切换" 结论之后会立即追问的战略问题 |

**关键缺失**：
- 报告没有正面回答**Connectors 的产品独立性问题**。如果 Connectors 这么强，它是否应该独立成 ACP 之外的产品？是否应该开源核心 + 商业化高级 feature？这些是 CEO 听完"不能替代" 之后**必然追问的下一组问题**，报告完全没碰。
- 建议在 §10.2 后或 §11 加一段 "**本报告未触及的战略问题**"：列出 (i) 是否独立产品化、(ii) 是否开源核心、(iii) 是否作为 ACP 标配 vs 可选模块、(iv) 是否对外提供 standalone 商业版——明确说"这些超出本调研范围，需独立战略评审"，避免 CEO 觉得调研团队没意识到这些问题。
